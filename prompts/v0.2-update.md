# Somidics v0.2 Update - January 2026

## Summary of Changes from v0.1

This document describes changes made to the somidics specification after initial design (v0.1). The core concept remains unchanged, but encoding has been improved for better discrimination.

## Critical Changes

### 1. Somid Size: 10 bits → 13 bits

**v0.1:** 10-bit somid + 8-bit CRC = 18 bits total
**v0.2:** 13-bit somid + 5-bit CRC = 18 bits total

**Impact:**
- Effective entropy: ~8-9 bits → ~11.9 bits
- Effective discrimination: ~1-in-500 → ~1-in-3,870
- Birthday paradox threshold: ~22 people → ~62 people
- Plane structure unchanged (still 18 bits = 262,144 per plane)

### 2. Zone Encoding: 5 bits → 6 bits

**v0.1:** 31 public zones (5 bits, with zone 31 as private flag)
**v0.2:** 48 public zones (6 bits, zones 0-47 public, 48-63 reserved)

**Key changes:**
- **Fingers subdivided:** 10 zones → 20 zones
  - Each finger split into "ring portion" (lower half with knuckle) and "upper portion" (upper half toward tip)
  - Natural language: "Scar on ring portion of left index finger"
- **Hands subdivided:** 4 zones → 8 zones
  - Each palm/back split into thumb-side and pinky-side
  - Natural language: "Mole on thumb-side of right palm"
- **Face expanded:** 8 zones → 10 zones
  - Added: Lips/around mouth (zone 28)
  - Split jaw into left (32) and right (33)
- **Private zone handling changed:** No longer uses special flag bit (zone 31)
  - Zones 48-63 reserved for private/future use
  - Cleaner design, no special cases

**Zone entropy:** 4.95 bits → 5.58 bits (gain: 0.63 bits)

### 3. Multiplicity Attribute Added: 1 bit

**New attribute (bit 12):**
- 0: Single mark
- 1: Cluster of marks (e.g., "three freckles grouped together")

**Entropy contribution:** ~0.88 bits (assuming 70% single, 30% cluster distribution)

**Natural language:** "Cluster of freckles on left cheek" vs "Single mole on left cheek"

### 4. Type Encoding Clarification

**v0.2 categories (no bit change, just clarification):**
- 00: Natural mark (mole, birthmark, freckle, discoloration, dimple)
- 01: Scar
- 10: Missing/Anomalous (missing fingertip, deformed ear, extra digit, webbed fingers)
- 11: Artificial/Intentional (tattoo, piercing, implant, scarification)

**Change:** Anomalous features moved from Type=11 to Type=10 (grouped with Missing)
**Rationale:** Both represent deviation from normal anatomy, vs. deliberate modification

### 5. CRC Strength: 8 bits → 5 bits

**v0.1:** CRC-8 rejects 99.6% of invalid codes (255/256)
**v0.2:** CRC-5 rejects 96.9% of invalid codes (31/32)

**Rationale:** 
- Still strong enough for error detection
- Bits better used for additional discrimination
- Total encoding space unchanged (18 bits)

## Complete v0.2 Bit Layout

```
Bit 0-5:   Zone (6 bits, 64 possible, 48 defined)
Bit 6-7:   Type (2 bits, 4 categories)
Bit 8-9:   Size (2 bits, 4 levels)
Bit 10-11: Texture (2 bits, 4 categories)
Bit 12:    Multiplicity (1 bit, single/cluster)
Bit 13-17: CRC-5 checksum

Total: 18 bits = 262,144 per plane (unchanged)
```

## Updated Entropy Analysis

### Theoretical Maximum
- Zone: log₂(48) = 5.58 bits
- Type: 2 bits
- Size: 2 bits
- Texture: 2 bits
- Multiplicity: 1 bit
- **Total: 12.58 bits**

### After Dependencies
**Known dependencies reduce entropy by ~0.65 bits:**
- Missing/Anomalous + Texture convention: -0.05 bits
- Artificial + Texture correlation: -0.15 bits
- Zone distribution non-uniformity: -0.30 bits
- Multiplicity + Type correlation: -0.15 bits

**Effective entropy: 12.58 - 0.65 ≈ 11.93 bits**

**Effective discrimination: 2^11.93 ≈ 3,870 possibilities**

## Backward Compatibility

**Breaking change:** v0.1 and v0.2 are **not compatible**

- Different bit layouts (10-bit vs 13-bit somid)
- Different CRC algorithms (CRC-8 vs CRC-5)
- Different zone maps

**Migration:** Credentials using v0.1 must be re-issued with v0.2 encoding

**Detection:** Can detect v0.1 vs v0.2 by attempting both CRC validations

## Implementation Changes

### CRC-5 Specification

**Algorithm:** CRC-5-USB (polynomial 0x05)
```
Polynomial: 0x05 (x^5 + x^2 + 1)
Initial value: 0x1F
Final XOR: 0x1F
Input reflection: true
Output reflection: true
Width: 5 bits
```

**Process:**
1. Take 13-bit somid
2. Compute CRC-5 over those 13 bits
3. Result is 5-bit value (0-31)

**New combined value:**
```
18-bit value = (somid << 5) | crc5
decimal = 18_bit_value + plane_offset
format as 6 digits
```

### Decoding Changes

**v0.2 decoding:**
```python
# Parse 6-digit input
value = int(somidic_string)

# Determine plane
if value >= 786432:
    return handle_special_value(value)
plane = value // 262144
offset = value % 262144

# Extract components (NEW bit positions)
crc5 = offset & 0x1F              # Last 5 bits
somid = (offset >> 5) & 0x1FFF    # First 13 bits

# Validate CRC-5 (NEW algorithm)
if compute_crc5(somid) != crc5:
    return "INVALID_CHECKSUM"

# Decode somid (NEW bit positions)
zone = (somid >> 7) & 0x3F        # 6 bits
type = (somid >> 5) & 0x03        # 2 bits
size = (somid >> 3) & 0x03        # 2 bits
texture = (somid >> 1) & 0x03     # 2 bits
multiplicity = somid & 0x01       # 1 bit
```

## Questions for Consideration

1. **Natural language for finger portions:**
   - Is "ring portion" and "upper portion" clear enough?
   - Alternatives: "knuckle area"/"tip area", "base half"/"tip half"?
   - User testing needed?

2. **Multiplicity encoding:**
   - Is single/cluster granular enough?
   - Should we distinguish 2 marks vs 3+ marks vs many?
   - Or is binary sufficient?

3. **Hand subdivision:**
   - Thumb-side/pinky-side is clear
   - But could we also distinguish finger-side/wrist-side (upper/lower palm)?
   - Would that be 4 zones per palm (thumb-upper, thumb-lower, pinky-upper, pinky-lower)?
   - Trade-off: more precision vs. more complexity

4. **Zone 48-63 allocation:**
   - Should we specify some private zones now or wait?
   - Candidate private zones: upper legs, feet, torso front/back, etc.
   - Medical examiner input needed?
