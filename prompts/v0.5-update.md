# Somidics v0.5 Complete Update Summary

## What Changed

### 1. Notation Format (BREAKING CHANGE)

**Old (v0.4):**
```
147293              # Single positive
@147293:582047      # Multiple positives  
147293-41           # With anti
-cf                 # Pure anti
```

**New (v0.5):**
```
@+147293            # Single positive
@+147293+582047     # Multiple positives
@+147293-41         # With anti
@-cf                # Pure anti
```

**Key changes:**
- All credentials now start with `@`
- Each positive somidic preceded by `+`
- Each anti-somidic preceded by `-` (separated, not concatenated)
- Operators represent set operations: `+` = union, `-` = difference

### 2. Read-Aloud Protocol (NEW)

**Trivial rules:**
- `@` = silent (implied context)
- `+` = say "PLUS"
- `-` = say "MINUS"
- Digits in groups of 3: "one four seven, two nine three"
- Always "zero" (never "oh")

**Example:**
```
@+147293+582047-41
→ "PLUS one four seven, two nine three, PLUS five eight two, zero four seven, MINUS four one"
```

### 3. Formal Decoding Specification (NEW - NORMATIVE)

Defines required structured output format for decoding credentials:

```json
{
  "positives": [
    {
      "zone": 32,
      "zone_name": "left_wrist",
      "type": 0,
      "type_name": "natural",
      "size": 2,
      "size_name": "coin",
      ...
    }
  ],
  "antis": [
    {
      "zone_flags": 1,
      "type_flags": 4,
      "zones": ["hands_fingers_wrists"],
      "types": ["tattoos"]
    }
  ]
}
```

### 4. Rendering Guidance (NEW - NON-NORMATIVE)

Provides templates for natural language descriptions:

**English example:**
- Standard: "Single raised coin-sized natural mark on left wrist"
- Compact: "Natural mark on left wrist"
- Anti: "No tattoos on hands, fingers, or wrists"

**Multi-language guidance included for adaptation**

### 5. Semantic Interpretation (NEW)

Mathematical reading of credentials:

```
@+P₁+P₂-A₁-A₂
= (P₁ ∪ P₂) \ (A₁ ∪ A₂)
```

Where:
- `+` represents set union (∪)
- `-` represents set difference (\)

- ✅ CRC-5 algorithm
- ✅ All zone definitions (48 public zones)
- ✅ Type/size/texture encoding
- ✅ Maximal compaction principle

**The changes are purely notational and procedural.**

## Benefits of v0.5

1. **Unambiguous**: Always starts with `@`, no confusion with other data
2. **Grep-able**: Can reliably find credentials in text with `@(\+\d{6}|-[0-9a-f]{2})+`
3. **Mathematical**: Notation directly represents set operations
4. **Trivial read-aloud**: Just say the operators you see
5. **Clear boundaries**: Each component explicitly marked
6. **Formal decoding**: Enables interoperability
7. **Rendering guidance**: Supports multi-language implementations

## Quick Reference

### Notation Regex Patterns

```regex
# Complete credential
^@(\+\d{6}|-[0-9a-f]{2})+$

# Find credentials in text
@(\+\d{6}|-[0-9a-f]{2})+

# Extract positives
(?<=\+)\d{6}

# Extract antis
(?<=-)[0-9a-f]{2}
```

### Reading Aloud Quick Guide

```
Symbol  Say
------  ----
@       (silent)
+       PLUS
-       MINUS
0       zero (not "oh")
a-f     letter name
```

## Summary

Somidics v0.5 represents a **notation and protocol formalization** while preserving all technical capabilities from v0.4. The system is now more usable, more clearly specified, and ready for implementation and standardization.

The breaking change in notation is justified by:
- Unambiguous parsing
- Mathematical clarity
- Trivial read-aloud rules
- Better user experience
- Formal specifications for interoperability

All documentation has been systematically updated and is ready for use.
