# Somidics v0.3 → v0.4 Update: Anti-Somidics

## Overview

Version 0.4 introduces **anti-somidics** - a compact way to encode negative assertions about body marks. An anti-somidic states "I do NOT have marks of type X in zone Y," providing powerful additional discrimination when combined with positive somidics.

**Key innovation:** Using just 2 hex digits (8 bits) per anti-somidic, credentials can now assert both what marks a person HAS and what marks they DON'T have.

## What Changed

### New Feature: Anti-Somidics

**v0.3 and earlier:**
- Could only assert positive claims: "I have a mole on my left wrist"
- Discrimination limited to positive somidics (single somidic ≈ 1-in-3,300)

**v0.4:**
- Can assert negative claims: "I have NO tattoos on my hands or face"
- Dramatically improves discrimination when combined with positive somidics
- Example: `147293-43` = "Mole on left wrist + no tattoos on hands/wrists or face"

### Notation Change

**New separator: hyphen (-)**

The hyphen semantically represents "subtraction" or "exclusion":

```
Before (v0.3):  147293
After (v0.4):   147293-43

Where:
147293 = Positive somidic (mole on left wrist)
43     = Anti-somidic (no tattoos on hands+wrists or face)
```

### Examples

**Single positive, single anti:**
```
147293-41
  Positive: Mole on left wrist
  Anti: No tattoos on hands+fingers+wrists
```

**Multiple positives, multiple antis:**
```
@147293:582047-43c1
  Positives: Two marks (scar on cheek, birthmark on hand)
  Antis: No tattoos on (hands+wrists or face), no piercings on hands+wrists
```

**Pure anti-somidics (professional credential):**
```
-cf
  No tattoos or piercings anywhere in public zones
```

## Anti-Somidic Encoding

### 8-Bit Structure (2 hex digits)

Each anti-somidic uses **8 bits encoded as 2 hex digits**:

```
Bits 0-3: Zone flags (4 bits)
  Bit 0: Hands + fingers + wrists (zones 0-33)
  Bit 1: Face (zones 34-43)
  Bit 2: Ears (zones 44-45)
  Bit 3: Neck (zones 46-47)

Bits 4-7: Type flags (4 bits)
  Bit 4: Natural marks (moles, birthmarks)
  Bit 5: Scars
  Bit 6: Tattoos
  Bit 7: Piercings/implants
```

### Why Flags Instead of Enumerations?

**Because zones and types are FLAGS (bitmasks), you can combine multiple zones and types in a SINGLE anti-somidic:**

```
0x43 (binary: 01000011)
  Zones: 0011 = hands+wrists (bit 0) + face (bit 1)
  Types: 0100 = tattoos (bit 6)
  
Meaning: "No tattoos on hands+wrists OR face"
```

```
0xC1 (binary: 11000001)
  Zones: 0001 = hands+wrists
  Types: 1100 = tattoos (bit 6) + piercings (bit 7)
  
Meaning: "No tattoos OR piercings on hands+wrists"
```

```
0xFF (binary: 11111111)
  Zones: 1111 = all zones
  Types: 1111 = all types
  
Meaning: "No marks of any kind anywhere in public zones"
```

### Common Anti-Somidics

```
11 = No natural marks on hands+wrists
12 = No natural marks on face
1f = No natural marks anywhere

21 = No scars on hands+wrists
2f = No scars anywhere

41 = No tattoos on hands+wrists
42 = No tattoos on face
43 = No tattoos on hands+wrists or face
4f = No tattoos anywhere

81 = No piercings on hands+wrists
82 = No piercings on face
8f = No piercings anywhere

c1 = No tattoos or piercings on hands+wrists
cf = No tattoos or piercings anywhere
ff = No marks of any kind anywhere
```

## Maximal Compaction Principle

### The Key Rule

**Anti-somidics are always maximally compacted** to minimize the number needed.

Since both zones AND types are bitmasks, you combine:
- Zone bits for marks with the same type constraints
- Type bits for marks with the same zone constraints

### Example: Full Compaction

```
User might think: "No tattoos on hands, no tattoos on face"

Naive encoding:  -4142
  41 = No tattoos on hands+wrists
  42 = No tattoos on face

Canonical form:  -43
  43 = No tattoos on (hands+wrists | face)
```

The system automatically combines these because they have the same type (tattoos).

### Example: Multiple Types

```
User might think: "No tattoos anywhere, no piercings anywhere"

Naive encoding:  -4f8f
  4f = No tattoos on all zones
  8f = No piercings on all zones

Canonical form:  -cf
  cf = No (tattoos | piercings) on all zones
```

### Maximum Anti-Somidics: 4

**Because of maximal compaction, you can have at most 4 anti-somidics in canonical form.**

This only occurs when you have **4 different zone patterns for the 4 type dimensions**:

```
-11224488
  11 = No natural marks on hands+wrists (zones=0001, types=0001)
  22 = No scars on face (zones=0010, types=0010)
  44 = No tattoos on ears (zones=0100, types=0100)
  88 = No piercings on neck (zones=1000, types=1000)
```

This is theoretically possible but practically absurd. **In practice:**
- **Most credentials: 0-1 anti-somidics**
- **Common: 1 anti-somidic** (like `4f` or `cf`)
- **Rare: 2-3 anti-somidics**
- **Very rare: 4 anti-somidics**

## Anti-Zone Design

### Why Only 4 Zones?

Anti-somidics use **broader zone categories** than positive somidics:

**Positive somidics:** 48 specific zones (left index finger upper portion, right cheek, etc.)
**Anti-somidics:** 4 broad zones (hands+wrists, face, ears, neck)

**Rationale:**
1. **Verification efficiency:** Scanning all fingers individually would be tedious
2. **Natural groupings:** "No tattoos on hands" is more natural than "no tattoos on left thumb AND left index AND..."
3. **Compactness:** 4 bits for zones (not 6)
4. **Asymmetry is useful:** Zone 0 (hands+fingers+wrists) can be checked even with long sleeves

### Zone 0: The Killer Feature

**Zone 0 = Hands + Fingers + Wrists (30 positive zones collapsed into 1)**

This is the most valuable anti-zone because:
- ✅ Can verify without disrobing (visible even with long sleeves)
- ✅ High coverage (30 positive zones)
- ✅ Culturally acceptable everywhere
- ✅ Professional dress compatible
- ✅ Many people have NO marks on hands/wrists/fingers

**Example:**
```
147293-41
  Positive: Birthmark on left cheek
  Anti: No tattoos on hands+fingers+wrists
  
Verification:
  1. Check left cheek for birthmark (15 seconds)
  2. Scan both hands, all fingers, both wrists for tattoos (45 seconds)
  Total: 60 seconds, no disrobing required
  
Discrimination: ~1-in-15,000
```

### Zone Mapping

```
Zone 0 (bit 0): Hands + fingers + wrists
  Covers positive zones: 0-19 (fingers), 20-27 (hands), 32-33 (wrists)
  
Zone 1 (bit 1): Face
  Covers positive zones: 34-43 (all facial zones)
  
Zone 2 (bit 2): Ears
  Covers positive zones: 44-45 (both ears)
  
Zone 3 (bit 3): Neck
  Covers positive zones: 46-47 (neck front and side/back)
```

## Override Principle

### Positive Somidics Are Exceptions

**Key rule:** Positive somidics always override anti-somidics in the same zone.

This allows natural expressions like:
```
147293-41
  Positive: "Tattoo with writing on right forearm" (zone 31)
  Anti: "No tattoos on hands+fingers+wrists" (zones 0-33)
```

**Wait - zone 31 (right forearm) is NOT in the anti-zone 0!**

- Zone 0: Hands + fingers + wrists = positive zones 0-27, 32-33 (NOT forearms 28-31)

So actually there's no conflict. Let me reconsider...

### Actually, Zone Coverage Needs Clarification

Looking back at the positive zone map:
- Zones 0-19: Fingers (ring and upper portions)
- Zones 20-27: Hands (palms and backs, thumb/pinky sides)
- Zones 28-31: **Arms** (upper arms and forearms)
- Zones 32-33: Wrists

**So anti-zone 0 should be "Hands + fingers + wrists" but NOT arms.**

Let me verify the zone coverage:
```
Anti-zone 0 (hands+fingers+wrists): 
  Positive zones 0-19 (fingers), 20-27 (hands), 32-33 (wrists)
  = 30 zones total
  
Anti-zone 1 (face):
  Positive zones 34-43 (face zones)
  = 10 zones total
  
Anti-zone 2 (ears):
  Positive zones 44-45 (ears)
  = 2 zones total
  
Anti-zone 3 (neck):
  Positive zones 46-47 (neck)
  = 2 zones total

Total coverage: 44 out of 48 public zones
Missing: Zones 28-31 (arms)
```

**Arms (zones 28-31) are NOT covered by any anti-zone!**

This is actually intentional - arms require exposing more skin, so we leave them out of anti-somidics for modesty reasons.

### Override Example (Corrected)

```
147293-41
  Positive: "Tattoo with writing on left wrist" (zone 32)
  Anti: "No tattoos on hands+fingers+wrists"
  
Zone 32 (left wrist) is IN anti-zone 0 (hands+fingers+wrists).

Interpretation: "I have a tattoo on my left wrist (this specific one),
                 but no OTHER tattoos on hands, fingers, or wrists"
```

The positive somidic creates an **exception** to the anti-somidic. The verifier:
1. Checks for the specific tattoo on left wrist ✓
2. Scans the rest of hands+fingers+wrists for OTHER tattoos ✓

### Override Logic

```python
def verify_anti_somidic(person, anti_value, positive_zones):
    """
    anti_value: 8-bit anti-somidic
    positive_zones: list of zones claimed in positive somidics
    """
    anti_zones = extract_zone_flags(anti_value)  # bits 0-3
    anti_types = extract_type_flags(anti_value)  # bits 4-7
    
    # Expand anti-zones to positive zone list
    expanded_zones = expand_anti_zones_to_positive_zones(anti_zones)
    
    # Remove zones that are already claimed in positives
    zones_to_check = [z for z in expanded_zones if z not in positive_zones]
    
    # Verify no marks of anti_types exist in zones_to_check
    return not has_marks(person, zones_to_check, anti_types)
```

## Verification Discretion

### Critical Principle: Verifier Chooses

**Anti-somidics are ALWAYS optional from the verifier's perspective.**

Whatever satisfies a verifier determines what must be done. If a credential contains anti-somidics but the verifier doesn't feel the need to check them, they don't have to.

**Low-security context (library card):**
```
Credential: 147293-cf
Verifier checks: Just the positive somidic (30 sec)
Verifier ignores: The anti-somidic
Result: Fast verification, acceptable discrimination
```

**High-security context (border control):**
```
Credential: 147293-cf
Verifier checks: Positive AND anti-somidics (120 sec)
Result: Slow verification, maximum discrimination
```

**This design means:**
- Credential holder pays no extra cost (just encode once)
- Verifier pays cost only when discrimination value justifies it
- System degrades gracefully (ignore antis = works like v0.3)
- Enables context-appropriate security

### Verification Policies

Different contexts will develop different policies:

```
Retail checkout:
  - Check first positive only
  - Ignore all anti-somidics
  - Time: ~30 seconds

Credit card (jewelry store):
  - Check all positives
  - Check up to 1 anti-somidic
  - Time: ~60-90 seconds

Government ID:
  - Check all positives
  - Check all anti-somidics
  - Time: ~2-3 minutes

Border control:
  - Check all somidics
  - Photograph for audit trail
  - Time: ~3-5 minutes
```

## Canonical Form Algorithm

### Compaction Process

```python
def canonicalize_anti_somidics(antis):
    """
    Maximally compact anti-somidics by combining zones and types.
    
    antis: list of 8-bit anti-somidic values
    returns: minimally sized list of anti-somidics
    """
    changed = True
    anti_tuples = [(a & 0x0F, a & 0xF0) for a in antis]
    
    while changed:
        changed = False
        new_tuples = []
        used = set()
        
        for i, (z1, t1) in enumerate(anti_tuples):
            if i in used:
                continue
            
            combined_z = z1
            combined_t = t1
            
            # Combine with other anti-somidics
            for j, (z2, t2) in enumerate(anti_tuples[i+1:], i+1):
                if j in used:
                    continue
                
                # Same zones? Combine types
                if z1 == z2:
                    combined_t |= t2
                    used.add(j)
                    changed = True
                
                # Same types? Combine zones
                elif t1 == t2:
                    combined_z |= z2
                    used.add(j)
                    changed = True
            
            new_tuples.append((combined_z, combined_t))
            used.add(i)
        
        anti_tuples = new_tuples
    
    # Convert back to 8-bit values and sort
    result = [z | t for z, t in anti_tuples]
    return sorted(result)
```

### Example Compaction

```
Input:  -41428182
  0x41 = No tattoos on hands+wrists
  0x42 = No tattoos on face
  0x81 = No piercings on hands+wrists
  0x82 = No piercings on face

Step 1: Combine 0x41 + 0x42 (same type, combine zones)
  → 0x43 = No tattoos on (hands+wrists | face)

Step 2: Combine 0x81 + 0x82 (same type, combine zones)
  → 0x83 = No piercings on (hands+wrists | face)

Step 3: Combine 0x43 + 0x83 (same zones, combine types)
  → 0xC3 = No (tattoos | piercings) on (hands+wrists | face)

Output: -c3
```

## Implementation Notes

### Validation Rules

**Anti-somidic validation:**
1. Must be pairs of hex digits (even length)
2. Each byte must have both nibbles non-zero
3. Must be in canonical form (maximally compacted, sorted)

**Invalid anti-somidics:**
```
00  - Both nibbles zero (meaningless)
01  - Type nibble zero (meaningless)
10  - Zone nibble zero (meaningless)
0f  - Type nibble zero (meaningless)
f0  - Zone nibble zero (meaningless)
```

**Valid range:** 0x11 through 0xFF (excluding x0 and 0x patterns)

### Parsing Grammar

```
somidic_set := positive_part [anti_part]
             | anti_part

positive_part := '@'? decimal6 (':' decimal6)*
anti_part := '-' hex_byte+

decimal6 := [0-9]{6}
hex_byte := [0-9a-f]{2}
```

### Regular Expressions

```regex
# Positive only (v0.3 compatible)
^@?\d{6}(:\d{6})*$

# With anti-somidics (v0.4)
^@?\d{6}(:\d{6})*-([0-9a-f]{2})+$

# Anti-somidics only
^-([0-9a-f]{2})+$

# Complete pattern (any valid somidic set)
^(@?\d{6}(:\d{6})*)?(-(([0-9a-f]{2})+))?$
```

## Design Rationale Summary

### Why 8 Bits (Not 4, Not More)?

**4 bits would be too limiting:**
- Could have zones OR types as flags, not both
- Wouldn't support "no tattoos on hands OR face"

**16+ bits would be overkill:**
- Don't need more than 4 zones or 4 types
- Compactness is valuable

**8 bits is perfect:**
- 4 zone flags + 4 type flags
- Can combine across both dimensions
- Fits in 2 hex digits (human-readable)
- Maximum 4 anti-somidics in canonical form

### Why Flags Instead of Enumerations?

**Enumerations (2 bits = 4 values) would require multiple anti-somidics:**
```
No tattoos on hands: -41
No tattoos on face:  -42
```

**Flags (4 bits) allow combination in ONE anti-somidic:**
```
No tattoos on hands or face: -43
```

This makes anti-somidics much more compact and elegant.

### Why Only 4 Anti-Zones?

**Could have matched all 48 positive zones:**
- Would need 6 bits for zones (64 possible)
- Would make anti-somidics less compact
- Verification would be tedious ("check each of 48 zones")

**4 broad zones are sufficient:**
- Natural groupings (hands, face, ears, neck)
- Easy to verify (scan entire face, etc.)
- Compact encoding (4 bits)
- Zone 0 is verifiable even with long sleeves (key feature)

### Why Maximal Compaction?

**Could allow redundant anti-somidics:**
```
-4142  = No tattoos on hands, no tattoos on face
```

**But canonical form is better:**
```
-43    = No tattoos on (hands | face)
```

**Benefits:**
- Shorter notation
- Faster to verify (one scan instead of two)
- Clearer semantics
- Less storage space
- Prevents confusion
